# 춤 관절 정보 만들기 (dance-joints)

춤 영상 목록(제목과 유튜브 링크, 또는 영상 파일)을 넣으면, 영상마다 춤추는 한 사람의 3D 관절 움직임을
파일로 만듭니다. 동작을 다른 몸(로봇, 캐릭터)으로 옮기는 변환기에 넣기 위한 것입니다.

```
python3 -B programs/dance-joints/dance_joints.py --list 목록.txt [--mirror auto|keep|flip] [--name 이름]
python3 -B programs/dance-joints/dance_joints.py --job <실행 폴더>     # 멈춘 작업 이어서
```

설치된 도구와 모델의 자리는 설정 파일에서 읽습니다(`DANCE3D_CONFIG` 또는 저장소 맨 위의 `config.local.json`, 보기 `config.example.json`). 키가 없거나 경로가 없으면 그 키와 설치 단계를 적은 한 문장으로 바로 멈춥니다.

화면: `joints_control.py start --open`(http://127.0.0.1:7864, 사용자 서비스 `dance-joints.service`, `joints_app.py`),
끄기는 `joints_control.py stop`. 화면은 위 명령을 실행하고 진행을 보여 줄 뿐입니다.
「멈춘 작업 이어서 하기」는 끝난 영상은 그대로 두고(알림 글만 새로 씀) 끝나지 않은 영상만 만듭니다.

목록은 한 줄에 영상 하나: `제목 링크`. 링크는 줄의 마지막 단어이고, 제목을 비우면 유튜브 제목을 씁니다.
빈 줄과 `#`로 시작하는 줄은 건너뜁니다.

## 하는 일 (영상마다, 끝난 단계는 이어 할 때 건너뜀)

| 단계 | 하는 일 | 쓰는 것 |
| --- | --- | --- |
| download | 유튜브에서 내려받기 (긴 변 1920 이하 화질) | yt-dlp |
| prepare | H.264, 원래 초당 장수(60까지), 긴 변 1920 이하. 거울모드 영상은 좌우를 되돌림 | `prepare_video.py` |
| track | 다른 사람보다 또렷이 큰 한 사람을 정하고 끝까지 같은 사람으로 따라감 | `track_one.py` (SAM 3) |
| cuts | 편집으로 장면이 통째로 바뀌는 곳 | `find_cuts.py` |
| flow | 배경이 화면에서 움직인 양(한 장마다) | duo-scene `qa_fast_motion.py` |
| geometry | 화각과 화면 속 바닥 | duo-scene `scene_geometry.py` (MoGe) |
| mocap | 3D 동작, 카메라 회전은 배경에서만 잼. 장면이 바뀌는 곳, 1초에 180°보다 빠른 "회전", 배경이 따라 움직이지 않은 "회전"은 재지 않음 | duo-scene `mocap_people.py` (ExMR, `--cuts`, `--max-turn-rate`, `--camera-flow`) |
| refine | 동작 추정이 뭉갠 빠른 움직임을 2D 관절로 되살림 | duo-scene `refine_motion.py` |
| world | 바닥 기준으로 바로 세우기, 안 보인 다리와 장면 잇기, 파일 쓰기 | `world_one.py` |
| check | 확인 영상 두 가지 | `check_video.py` |

내려받기는 동작 단계보다 앞서 가고, cuts와 flow(CPU)는 geometry(GPU) 옆에서, 한 영상의 world와 check(CPU)는 다음 영상의
동작 단계(GPU) 옆에서 돕니다. 단계의 프로그램이 바뀌면 이어 할 때 그 단계부터 다시 합니다.
끝난 영상은 바로 결과 폴더(설정 `results_dir`)에 들어가고, 모두 끝나면 `결과_안내.txt`를 씁니다.
실패한 영상은 까닭을 적고 나머지는 계속합니다.

동작 단계는 2인 캐릭터 춤 프로그램(`programs/duo-scene`)의 것을 그대로 씁니다.
그 폴더의 `paths.py`가 설정 파일에서 모델과 실행기 위치를 읽고, 캐시는 이 실행의 실행 폴더 안에 둡니다(`DUO_JOB`).

## 정한 규칙과 까닭

- **누구를 뽑나**: 화면에서 가장 큰 사람이 다음 사람보다 두 배 넘게 큰 장면 가운데, 몸 전체가 화면 안에 있고 앞뒤 7장 동안
  꾸준히 잡히는 장면을 기준으로 정합니다. 연습실 거울에 비친 모습이나 지나가는 사람이 있어도 되지만 또렷이 작아야 합니다.
  거기서 앞뒤로 따라가므로 나중에 가까이 온 사람으로 바뀌지 않습니다.
- **위쪽 방향**: 동작 추정(ExMR)은 몸만 보고 중력 방향을 정해서, 손으로 들고 기울여 찍은 카메라를 반듯하다고 여기고
  기울기를 몸에 넣습니다(11-14 2인 프로그램에서 잰 것). 화면에 바닥이 보이면 그 바닥을 위쪽 방향으로 삼아 몸을 바로 세웁니다.
  단, 사람이 그 바닥을 실제로 디디고 있을 때만: 화면 속에서 디딘 발을 지나는 시선이 잰 바닥과 만나는 거리가 동작 추정의
  발 거리와 영상 내내 같은 비율이어야 합니다(15 % 안에 든 비율이 70 % 이상). 11-14에 잰 값: 실제 촬영 영상 셋 88~100 %,
  그린스크린으로 게임 배경을 합성한 영상 42~54 %, 벽과 바닥이 거울처럼 비치는 연습실 52 %. 아니면 바닥을 쓰지 않고 동작
  추정 그대로 두며 결과_안내.txt에 적습니다. 바닥은 장면마다 따로 잽니다(장면이 바뀌면 카메라도 바뀜). 사람 몸의 위쪽과 30°
  넘게 어긋나는 면은 바닥으로 보지 않습니다: 손에 든 카메라의 기울기는 18°까지 쟀고, 「캐치캐치」의 가까운 장면에서
  바닥으로 잡힌 면은 36~72° 기운 벽이었습니다.
- **편집**: 장면이 바뀌거나 배경이 옆으로 밀려 바뀌는 곳에서 배경 맞추기는 카메라가 100° 넘게 돈 것으로 읽고, 그러면 춤추는
  사람이 뒤로 돌아선 것처럼 나옵니다(11-14 「L을가져가」에서 107°, 141°). 실제 영상 셋에서 카메라는 1초에 160°보다 빨리
  돈 적이 없고 편집 전환은 1초에 400~530°였으므로, 1초에 180°보다 빠른 "회전"과 장면이 통째로 바뀌는 곳(`find_cuts.py`:
  사람을 뺀 배경이 한 장 사이에 크게 바뀜)에서는 카메라를 그대로 둡니다. 장면이 바뀐 뒤에는 사람의 방향과 자리가 이어지도록
  세계를 돌리고 옮기며, 부드럽게 하기와 손떨림 빼기도 장면을 넘어가지 않습니다.
- **배경이 따라오지 않은 회전**: 카메라가 정말 돌면 배경 전체가 화면에서 그만큼 밀립니다. 조명이 바뀔 때 배경 맞추기가
  카메라가 서 있는데도 26~29°씩 돈 것으로 읽었습니다(「REDRED」, 1초에 105°라 위의 속도 기준에 안 걸림). 한 번 잴 때
  화면 가운데를 화면 너비의 1/4보다 멀리 옮길 회전인데, 배경은 그 방향으로 그 35 %도 움직이지 않았으면 재지 않습니다.
  이 기준은 앞서 만든 실제 영상 셋(손에 든 카메라 포함)에서 한 번도 걸리지 않았습니다. 이보다 작은 가짜 회전은 남을 수
  있습니다(「REDRED」 12초 뒤 약 15°).
- **화면 밖의 다리**: 셀카처럼 다리가 화면 밖인 장면에서 동작 추정은 쪼그린 다리를 지어내고, 그러면 위아래 움직임이 크게
  나옵니다(「L을가져가」 앞 1.6초: 골반 0.46~0.58 m). 두 발목이 화면 안에 또렷이 보이지 않는 장면은 다리 관절과 골반 높이를
  다리가 보이는 앞뒤 장면에서 이어 붙이고(`legs_estimated`), 카메라도 같은 높이만큼 옮겨 윗몸은 화면과 맞게 둡니다.
- **빠른 움직임**: 동작 추정의 세계 좌표 움직임은 부드럽게 뭉개져 튕기기·흔들기가 1/4~1/3 작아집니다. 카메라 기준 몸을
  0.1초로 다듬은 카메라 위치로 세계에 옮기고, 2D 관절과 맞춰 빠른 부분을 되살립니다. 마지막에 9 Hz보다 빠른 떨림은 지웁니다.
- **안 보인 장면**: 사람이 또렷이 보이지 않는 장면(몸 관절 6개 미만이 사람 영역 안에 잡힘)은 동작 추정의 짐작을 쓰지 않고
  앞뒤 장면을 이어 붙이며 `estimated = 1`로 표시합니다.
- **거울모드**: 연습용 거울모드 영상은 좌우가 뒤집힌 화면입니다. 그대로 뽑으면 왼손·오른손이 바뀐 안무가 됩니다.
  제목(목록의 제목 또는 유튜브 제목)에 `거울모드`, `미러모드`, `좌우반전`, `mirror mode`, `mirrored`, `mirror ver`가 있으면
  화면을 좌우로 되돌린 뒤 뽑습니다(`--mirror auto`, 기본). `keep`은 화면 그대로, `flip`은 모두 되돌립니다.
  제목에 적혀 있지 않은 거울 영상(휴대폰 앞 카메라 등)은 알아내지 못합니다.

## 결과

결과 폴더 `<results_dir>/<실행 폴더 이름>/`:

- `결과_안내.txt`: 영상마다 길이, 사람이 보인 비율, 바닥 기준 비율, 카메라 기울기, 관절과 화면의 차이, 알림
- `파일_설명.txt`: 아래 파일 형식과 관절 76개 목록
- `NN_제목/results.npz`: 「3D 모캡 H3」의 `outputs/mocap/results.npz`와 같은 키와 모양(ExMR `docs/OUTPUTS.md`).
  다른 점: `smplx_global_*`, `joints_global`은 위 규칙으로 바로 세운 값이고, 초당 장수는 원본 그대로이며
  `reliable`, `estimated`, `floor_trust`, `turned_to_floor_deg`, `camera_R_c2w`, `camera_center`, `flipped_left_right`가 더 있습니다.
  y가 위, 바닥이 y = 0, 미터.
- `NN_제목/motion.bvh`(SMPL-X 관절 55개, 센티미터, y 위), `motion_amass.npz`(AMASS SMPL-X, z 위)
- `NN_제목/관절_정면과_옆.mp4`: 관절만 정면과 옆에서 본 영상(원본 화면 없음)
- `검증용_원본포함_공유금지/NN_제목_원본_위_관절_원본포함.mp4`: 원본 위에 세계 좌표의 관절을 카메라로 비춰 그린 것. 밖으로 내보내지 않습니다.

실행 폴더 `<runs_dir>/<실행 폴더 이름>/outputs/videos/NN/`에 단계별 결과와 기록(`logs/`, `stages/`)이 남습니다.
`work/joints/report.json`에 자동 확인 수치가 있습니다. results.npz에는 `legs_estimated`(다리를 이어 붙인 장면)도 있습니다.

## 지키는 것

실행 폴더 하나(설정 `runs_dir` 아래 날짜 폴더, 또는 `managed_jobs` 이면 GPU 도우미의 작업 폴더)에 모든 쓰기를 둡니다.
설정에 `gpu_helper` 가 있으면 실행 전체에 GPU 임대 하나(갱신, 끝나면 반드시 반납), 없으면 보이는 GPU 를 씁니다.
원본 영상이 보이는 파일은 실행 폴더와 `검증용_원본포함_공유금지` 폴더에만 둡니다.

## 확인한 것과 못 한 것

2026-11-14, 주인이 준 쇼츠 15개(모두 한 사람, 14~40초, 합쳐서 6분 44초, 초당 24·30·60장, 1080×1920~2160×3840).
거울모드 연습 영상 8개, 그린스크린에 게임 배경을 합성하고 배경이 밀려 바뀌는 챌린지 1개, 끝에 로고 화면이나 가까운
장면으로 바뀌는 것, 셀카 장면, 조명이 바뀌는 연습실, 거울 벽 연습실, 밤 야외가 섞여 있습니다.

- 마지막 실행(2026-11-14): 화면의 「전체 실행」으로, 손대지 않고 15개 모두 49분.
  관절과 화면 속 사람의 차이는 몸 높이의 1.2~1.6 %(중간값), 나쁜 장면 10 %도 3.4 % 안쪽. 바닥에 디딘 발의 높이 3~4 cm.
  15개 확인 영상을 모두 처음부터 끝까지 2초 간격으로 보았습니다(원본 위 관절, 정면, 옆).
  끝난 뒤 「멈춘 작업 이어서 하기」를 한 번 눌러 `관절_파일_모음.zip`을 만들었습니다(영상은 다시 만들지 않음).
- 그 전 실행에서 확인 영상을 보고 찾아 고친 것: 시험 두 번에서 편집 전환을 카메라 회전으로 읽음, 합성 배경의
  가짜 바닥, 셀카 장면의 지어낸 다리. 첫 15개 실행(44분)에서 세로 1918 영상 실패, SAM 3 추적 실패, 조명 변화를
  회전으로 읽음. 둘째 15개 실행(49분)에서 장면이 바뀐 뒤 벽을 바닥으로 삼음. 모두 위 규칙이 되었습니다.
- 카메라 회전 검사(배경 움직임)는 2인 프로그램 때의 실제 영상 셋(손에 든 카메라 하나 포함)에서 걸리지 않는 것을 CPU로만
  확인했습니다. 이번 15개는 카메라가 거의 서 있는 영상이라, 크게 움직이는 손 카메라 영상은 이 프로그램으로 돌려 보지 않았습니다.

못 한 것과 한계
- 결과를 받을 변환기(다른 PC)에 넣어 보지 않았습니다. 형식은 1인 프로그램의 results.npz와 키·모양·자료형이 같습니다.
- 거울모드를 되돌릴지 물었더니, 주인은 어느 쪽이든 상관없다고 했습니다(11-14). 기본(`--mirror auto`, 되돌림)을 그대로 둡니다.
- 작은 가짜 회전은 남을 수 있습니다: 「REDRED」 12초 뒤 약 15°, 「갑자기」에도 무늬 없는 배경에서 비슷한 오차가 있을 수 있음.
- 화면 밖이나 가려진 몸은 추정입니다. 제목에 적히지 않은 거울 영상은 알아내지 못합니다. 여러 명이면 가장 큰 사람 하나입니다.
